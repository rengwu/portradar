# PortRadar: handoff

PortRadar is a minimal macOS menu bar app. It lists the dev servers and local services that are listening on a port, and opens or copies their address with one click. It follows the same approach as `../klip` and `../yacht`: Swift and AppKit, no dependencies, macOS 13+, ad-hoc signed, and a `*Core` library with no AppKit that is tested by a plain executable. This machine has Command Line Tools only, so there is no XCTest.

Status as of 2026-11-17: **the core and the app are written and `./build.sh` produces `build/PortRadar.app`.** Drawing is checked by screenshot. Pointer interaction (hover submenu, clicks) is not yet confirmed; see Verification.

## Accepted design (two grill-form rounds)

**Layout.** There are two modes, chosen in **Settings only**. The dropdown has no mode toggle.

- **Grouped (default).** A dim header for each project. Each row reads `:4178   tools/admin-gallery            Vite`: the port in monospaced type, the detail, then the kind dimmed and right-aligned. Rows have no coloured dots, badges, or separator characters such as `·`. Services without a project go under a final "Other" header.
- **Simple.** A flat list sorted by port. Each row reads `:4178   quinecms            Vite`, with the project name as the title.

**Row interaction.**

- Clicking the row opens `http://localhost:PORT` in the default browser.
- On hover, the right side shows copy and open icons in place of the kind.
- Each row also has a **native nested submenu**, like Tailscale's menu. See `attachments/nested-submenu-reference.png`. It contains Open in Browser, Copy URL, a separator, Reveal in Finder (the project folder) and Stop Process.
- Stop sends SIGTERM straight away, with no confirmation. If the process is still alive afterwards, the item becomes **Force Quit** (SIGKILL) the next time the menu opens.

**Menu bar.** The icon is a template image with no count. It is dimmed (`button.appearsDisabled`) when no visible services are running. The glyph is the radar app icon in one colour, in `Resources/MenuBarIcon.svg` (see Icons below).

**Hidden section.** The last section is a "Hidden" header with a count and a chevron. Clicking it shows or hides its rows in place. Its menu item has no action and the view toggles on mouse down: with an action, the user's second click (to collapse) closed the whole menu. The cost is that the header cannot be reached from the keyboard. This replaced a "Show N Hidden" menu entry, which the user rejected as tacky on 2026-11-17 (other options offered: a submenu, hold ⌥, a Settings checkbox).

**Footer.** Settings… (⌘,) and Quit PortRadar (⌘Q).

**Hidden by default.** Listed in `ServiceCategory`:

- macOS daemons
- GUI apps
- coding-agent CLIs (codex, claude…), which sit on random high ports
- unknown processes on an ephemeral port (≥ 49152) or outside any project

The last rule goes slightly further than what the user picked, which was only "ephemeral, unknown". Mention it if it causes surprises.

**Address.** Always `http://localhost:PORT`.

**Extras.** Stop process, reveal folder, launch at login. These were explicitly declined: open in editor, uptime, notifications, global hotkey, rename or pin, Docker container names.

The prototype generators are kept in `attachments/gen1.mjs` and `attachments/gen2.mjs`. They produce the grill-form JSON, and grill-form is `../jstack/skills/grill-form`.

## What exists

| File | Purpose |
|---|---|
| `Package.swift` | Targets `PortRadarCore`, `PortRadar`, `PortRadarCoreTests` |
| `Sources/PortRadarCore/Scanner.swift` | libproc scan of listening TCP sockets (`proc_pidinfo` LISTFDS → `proc_pidfdinfo` SOCKETINFO), cwd (`PROC_PIDVNODEPATHINFO`), argv (`KERN_PROCARGS2`). Merges IPv4 and IPv6 and inherited fds per port, keeping the lowest pid. About 11 ms for 19 listeners. |
| `Sources/PortRadarCore/ProjectResolver.swift` | Finds the nearest ancestor with `.git`, else the nearest manifest. Never `~`, `/` or system paths. Falls back to the script's directory. Cached. |
| `Sources/PortRadarCore/Classifier.swift` | `Identity(kind, detail, category)`. JS framework = the npm package that owns the script under `node_modules`. Also handles Python `-m` and entry points, Next's `next-server` title, `go run`, cargo `target/`, known binaries (Postgres, Redis, Docker…), system paths, `.app` bundles, agents. |
| `Sources/PortRadarCore/Presentation.swift` | `identify(listeners, resolver:)` → `[Service]`; `present(services, layout:, showHidden:)` → `MenuModel` (sections, rows, visible and hidden counts). |
| `Tests/PortRadarCoreTests` | 42 passing checks, using fixtures taken from real command lines on this machine. `swift run PortRadarCoreTests --live` also prints a live scan. |

Live scan on this machine: 5 dev rows (`4178` Vite, `4179` Python http.server, `4321` and `4322` Node quinecms, `4410` vite preview) and 14 hidden ones (codex, claude, Discord, rapportd).

## The app (`Sources/PortRadar/`)

| File | Purpose |
|---|---|
| `main.swift` | `.accessory` policy. |
| `AppDelegate.swift` | Status item, 3 s rescan timer (dimmed state only, skipped while the menu is open), menu built in `menuNeedsUpdate`, submenus, stop and Force Quit, settings. |
| `MenuViews.swift` | `HighlightView` puts an `NSVisualEffectView` (`.selection`, emphasized) behind the content, which matches the native highlight exactly. `ServiceRowView` draws the row, hover icons and its own chevron. `DisclosureHeaderView` is the "Hidden" header. Hidden rows are always built and toggled with `NSMenuItem.isHidden`; rebuilding an open menu with `removeAllItems` left empty space under the last item. `ActionItem` is a closure menu item. |
| `MenuBarIcon.swift` | The glyph, drawn in code as a template image. |
| `SettingsWindowController.swift` | Grouped or Simple radio (`UserDefaults` key `layout`) and launch at login. |
| `LaunchAtLogin.swift` | Copied from Yacht, bundle id `local.portradar`. |
| `Demo.swift` | `--demo` uses fixed services and logs actions to stdout instead of performing them. Extra flags: `--open` (open the menu at launch), `--simple`, `--hidden`, `--light`, `--dark`, `--highlight N` (draw row N highlighted), `--stubborn` (stopped services stay, to show Force Quit), `--settings`. |

Findings worth keeping:

- Highlight state comes from the delegate's `menu(_:willHighlight:)`, not from `enclosingMenuItem.isHighlighted` in `draw`.
- Native rows on macOS 27 are 24 pt high with text at x = 17, and the highlight is inset 5 pt with a 7 pt radius.
- `build.sh` copies each architecture's binary out before building the next. Swift 6.4's SwiftPM writes both to `.build/out/Products/Release`, so Yacht's script as written fails at `lipo` here.
- `NSApp.appearance` does not restyle a status item menu; set `menu.appearance` (macOS 14+).

## Verification

Checked on 2026-11-17, macOS 27.0, Swift 6.4.2, debug build:

- `swift run PortRadarCoreTests`: 42 pass.
- Screenshots of the real status item menu in demo mode: grouped, simple, hidden shown, a highlighted row, light and dark, and the settings window. A live (non-demo) scan also listed the five real dev servers. The current demo screenshot is `docs/assets/portradar-demo.png`.
- `./build.sh`: universal (`x86_64 arm64`), ad-hoc signed, identifier `local.portradar`.

The user tried the demo on 2026-11-17 and confirmed, with the action log agreeing: submenu on hover, highlight following the pointer with hover icons, the copy icon's "Copied", in-place expansion, and Stop Process becoming Force Quit. The expanding Hidden header was then checked by toggling it from a timer in an open menu: the menu grows and shrinks with no leftover space.

Not checked by the agent: anything that needs a pointer. Simulated pointer and key events do not reach an open menu without Accessibility permission (`CGEvent.post` is dropped; `NSApp.postEvent` is ignored by menu tracking). That covers submenu on hover, row clicks, the copy icon, in-place Show Hidden, and Stop then Force Quit. Opening the menu from a script also steals the keyboard from whatever the user is typing in, so keep such runs rare.

To capture only PortRadar's menu, find its windows with `CGWindowListCopyWindowInfo` (owner `PortRadar`, layer 101) and run `screencapture -l <id>`.
